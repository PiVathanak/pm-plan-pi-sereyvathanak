## Grey zones

**Row 9 (annual IT report).** It looks like an operation because it recurs every year, and like a project because each edition has a deadline, a deliverable, and a team. What settles it is whether the report is a standing duty with a fixed template (operation) or whether this edition changes scope or format, such as new metrics or a new audience (project). I treated this as an operation because it is more into action or behavoir of the project rather than the project itself.

**Row 10 (replacing 40 access points).** The summer window and the defined end state make it a project. But once the first few are done, the rest are the same repeated task, which is how operations work. What settles it is whether the replacement needs planning of its own (site survey, channel plan, new controller config), which makes it a project, or is just a like-for-like swap from a checklist, which makes it routine maintenance.

## What our project hands over

The Realtime Quiz build project ends at the week 14 pilot and hands over a working, deployed platform, plus the documentation and runbooks needed to run it (restart steps, monitoring, password reset procedure). It also hands over admin access and credentials, and a trained operator who can take over day-to-day support. From that point, row 8 (operation) takes over, and any new capability, such as multi-node scaling in row 7, goes back through a separate project.
